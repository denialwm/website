大部分配置都可以在 Denial 设置中完成，并在会话运行期间应用。显示状态会作为一个事务
整体验证，避免留下无效的部分布局。

## 设置

设置分为以下实用类别：

| 页面 | 控制内容 |
| --- | --- |
| 外观 | 强调色来源、圆角半径、不透明度、模糊和焦点窗口效果 |
| 动画 | 动画速度、面板运动、锁定动画和窗口关闭效果 |
| 桌面布局 | 系统栏位置、所选显示器、厚度和最大化留白 |
| 浮层 | 启动器、仪表板、通知和系统 HUD 的位置与大小 |
| 锁屏 | 壁纸、变暗、模糊、时钟缩放和状态可见性 |
| 音频 | 输出音量、静音状态和应用音频流 |
| 显示与视频 | 已连接输出的模式、刷新率和缩放详情，以及亮度 |
| 网络 | Wi-Fi 状态、连接和已保存的配置文件 |
| 蓝牙 | 适配器状态、发现、配对和已连接设备 |
| 电源 | 空闲时关闭显示器的行为和可用性能模式 |
| 开发者 | Flutter 桌面外壳运行时和实时开发控制 |

在**外观**中，用于模糊的最低窗口不透明度决定 Denial 何时停止为几乎透明的窗口渲染
背景模糊。提高它可以跳过更多低不透明度下的模糊工作，降低它则可让模糊在透明度变化
过程中保留更久。完全不可见的窗口永远不会请求背景模糊。

桌面外壳偏好存储在：

```text
~/.config/denial/settings.json
```

该文件带有版本并由桌面外壳管理。建议通过设置界面修改它。

## 输出配置

首次登录时，打包的输出模板会复制到：

```text
~/.config/denial/outputs.conf
```

现有用户文件不会被替换。如果没有针对连接器的条目，Denial 会发现已连接的显示器、
自动排列它们，并为每台显示器选择原生分辨率下最快的模式。

使用以下命令查看连接器名称和活动模式：

```sh
denialctl outputs
```

一个小型固定布局可能如下所示：

```ini
eDP-1=0,0,120
DP-1=2560,0,144
scale=DP-1,1.25
vrr=DP-1
system_bar=top,32,eDP-1
maximize_padding=10
```

支持的条目如下：

| 条目 | 含义 |
| --- | --- |
| `NAME=X,Y` | 将输出放在桌面的逻辑坐标中 |
| `NAME=X,Y,HZ` | 放置输出并请求指定刷新率 |
| `mode=NAME,WIDTH,HEIGHT,MILLIHZ` | 选择精确的输出模式 |
| `scale=NAME,SCALE` | 设置小数或整数缩放 |
| `vrr=NAME` | 启用可变刷新率 |
| `disabled=NAME` | 保持已连接的输出处于禁用状态 |
| `system_bar=EDGE,SIZE[,OUTPUT]` | 放置系统栏 |
| `system_bar=hidden` | 隐藏系统栏 |
| `maximize_padding=PIXELS` | 在最大化窗口周围保留空间 |

`EDGE` 可以是 `top`、`bottom`、`left` 或 `right`。多个系统栏输出可以用 `+` 连接，
例如 `eDP-1+DP-1`。

当前设置页面会报告每个活动模式、刷新率和缩放并控制亮度；它还不能编辑输出位置、模式、
缩放或可变刷新率。请在 Denial 未运行时修改 `outputs.conf` 中的这些条目。手动修改会在
下次会话启动时生效，Denial 会先验证完整布局，再应用它。

### 显示缩放

输出缩放是物理显示像素与 Denial 逻辑桌面坐标之间的比例。例如，`1.25` 表示 125%，
`1.5` 表示 150%。输出位置、窗口几何、系统栏厚度和最大化留白仍使用逻辑像素；Denial
会以所需的物理分辨率渲染桌面，而不是放大一张已经完成的图像。

支持小数缩放的 Wayland 应用会收到当前所在输出的精确缩放值。较旧的 Wayland 应用会
收到下一个整数缩放值并被缩小显示，这会优先保证内容清晰，而不是放大 1x 缓冲区。

Xwayland 在整个会话中只能使用一个缩放值，因为单个 X 服务器无法为每个 X11 窗口提供
不同的坐标缩放。Denial 会选择不小于最大活动输出缩放值的最小整数，并发布匹配的 X11
DPI 提示。例如在 1.5x 桌面上，能识别 DPI 的 X11 应用会以 2x 渲染，再缩小到 1.5x。
忽略 X11 DPI 提示的应用可能看起来比预期更小，在混合缩放布局中尤其如此。

> [!WARNING]
> 显示缩放目前是初步实现。1.5x 路径已经过测试；1x、混合缩放布局、在不同缩放输出间
> 移动窗口以及运行时更改缩放仍需更广泛的验证。更改后请运行 `denialctl outputs`，确认
> 活动的逻辑布局和缩放。

## 机器级覆盖

管理员覆盖项应放在：

```text
/etc/denial/session.conf
```

启动器通常会选择连接了显示器的启动 GPU。只有当显示连接器路由到另一个 DRM 设备时，
才设置 `DENIAL_DRM_DEVICE`：

```ini
DENIAL_DRM_DEVICE=/dev/dri/by-path/pci-0000:01:00.0-card
```

同一个文件还可以覆盖 Flutter bundle 或用户输出配置路径，并启用原生调试日志。个人桌面
偏好应保留在设置中，而不是写入这个机器级文件。

### 渲染器后备 {#renderer-fallback}

Denial 默认使用与合成器集成的 Impeller GLES 路径。如果某个 GPU 或驱动存在渲染问题，
可以在 `/etc/denial/session.conf` 中选择保留的 Skia/Ganesh 后备：

```ini
DENIA_FLUTTER_RENDERER=skia
```

更改渲染器后，请重启 Denial 会话。删除该覆盖项，或将它设为 `impeller`，即可恢复默认值。
如需进行一次受控启动，等效的直接参数是 `denial-session --flutter-renderer skia`。
