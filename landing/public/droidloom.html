Droidloom

Android apps,
as real Linux windows.

Droidloom runs a real Android userspace on your Linux kernel and gives every app its own Wayland window. GPU accelerated, zero-copy, and open source from top to bottom.

Try the preview GitHub

Why it’s different

Not an Android desktop in a box.

Other approaches boot a whole Android session and hand you one big window to live inside. Droidloom takes Android apart and puts each app on your desktop as its own window, next to everything else.

01

One window per app

Every Android task becomes its own xdg_toplevel. Tile it, resize it, move it between workspaces, close it from your compositor. Android gets the new geometry and lays itself out again, the way a native app would.

02

Real Android, no VM

ART, Binder, Zygote and system_server run directly on the host kernel in their own namespaces, with a private binderfs instance. No second kernel, no emulator, no container image to babysit. Android apps show up in htop like any other process.

03

Zero-copy graphics

App buffers reach the compositor as DMA-BUFs with explicit synchronization. Eligible layers skip Android’s own composition entirely: the compositor samples the app’s original buffers, with no intermediate render and no copies.

04

No closed-source blobs

Mesa for graphics, Teto for ARM translation, and Droidloom itself under GPL-3.0-or-later.

Desktop integration

Feels like it was always there.

  • In your app launcher

    Android apps are exported as regular desktop entries, with names and icons, updated live as you install and remove them.

  • Clipboard, both ways

    Text, links, HTML, images and copied files move between Android and Linux apps.

  • Native notifications

    Android notifications appear as desktop notifications. Clicks and actions open the app; dismissing on the desktop clears them in Android.

  • Your keyboard

    Text fields use the compositor’s own input method. Android never draws a keyboard of its own.

  • Desktop or mobile mode

    Phone-sized windows that remember their size, or apps that fill the screen. Choose per app.

  • Debuggable

    droidloomctl logs and droidloomctl crashes work as your user, without sudo, even while Android is still booting.

Better with Denial

Built together, down to the protocol.

Droidloom works on any modern Wayland compositor. On Denial it goes further: the two speak dedicated Wayland protocols, so Android apps behave as if Denial were their own system UI.

denial_insets_v1

Status bar and navigation spacing

Denial tells Android where its status bar and bottom navigation indicator are. Apps receive real WindowInsets and lay their content around Denial’s bars, exactly as they would on a phone.

denial_frame_timeline_v1

Exact frame timing

Denial grants each frame with a latch deadline and a presentation target. Android renders for the exact refresh Denial will show, instead of guessing.

denial_text_input_panel_v1

On-screen keyboard

Android’s show and hide keyboard requests drive Denial’s on-screen keyboard directly, and dismissing it stays dismissed.

The protocols are product-neutral and documented in the Droidloom repository. Any compositor can implement them.

What runs

Native on ARM, translated on x86 when needed.

ARM64 · phones and tablets

Nearly anything.

On ARM devices, Android apps run natively on the same architecture they were built for. If it runs on Android, expect it to run on Droidloom.

x86_64 · desktop

Most things, through Teto.

Apps with x86_64 builds run natively. ARM-only apps and games run through Teto, an open-source ARM64 translation engine based on Android’s Berberis. Most apps work; games depend on what Teto supports, and that list keeps growing.

  • Neverness to Everness
  • Brawl Stars
  • Clash of Clans

Droidloom is made by one developer. If it runs an app you rely on, sponsoring funds the work on it.

Support Droidloom

Try it

Try the preview.

The desktop preview targets x86_64 Arch Linux and Omarchy with AMD or Intel graphics. You need a Wayland session and about 20 GiB of free space. NVIDIA rendering is not validated yet.

  1. Install the packages

    Download and read the installer, then run it. It adds the Droidloom pacman repository and installs the runtime and the Android image. Updates arrive through your normal pacman -Syu.

    $ shell · install 
    curl -fLO https://denialwm.github.io/droidloom/install.shless install.shsh install.sh

  2. Start Android and install apps

    Run these from your Wayland session as your normal user. The first start asks for administrator access once to set up Android’s data.

    $ shell · first run 
    droidloomctl startdroidloomctl install ~/Downloads/app.apkdroidloomctl launch com.android.settings
